ADR-035 Возобновляемый авторизованный SSE для durable Job
Статус: accepted by GPT; implements existing canonical 1.5.0 operation.
Дата: 2026-10-30. Основа: ADR-026/030/034, streamJobEvents in canonical OpenAPI.

ПРОБЛЕМА

Клиент C4 и экран теней опрашивают getJob. Канонический контракт уже содержит
`GET /v1/jobs/{job_id}/events`, но сервер не объявлял и не реализовывал операцию. Простое открытие
потока без повторной авторизации создало бы утечку после отзыва grant/session.

РЕШЕНИЕ

- Endpoint перед отправкой заголовков выполняет обычную session/role/city/owner/input
  авторизацию Job. Не владелец получает тот же скрывающий 404; admin сохраняет действующую
  canonical политику.
- Каждая строка append-only `job_events` передаётся как `event: job`, `id` равен глобальной
  sequence, `data` валидируется как canonical JobEvent.
- `Last-Event-ID` и `after_event_id` возобновляют поток строго после подтверждённого события
  этого Job. Несовпадающие или чужие cursors отклоняются до открытия потока.
- Доступ перепроверяется при каждом чтении. После отзыва поток закрывается без раскрытия причины,
  поскольку HTTP status уже отправлен.
- Heartbeat comment удерживает прокси-соединение. После доставки terminal transition поток
  дочитывает возможную последнюю страницу и закрывается.

ГРАНИЦЫ

Это polling PostgreSQL внутри server-side SSE, а не Redis pub/sub. Он устраняет клиентский polling
и обеспечивает resume, но production proxy должен отключать buffering и иметь подходящий idle
timeout. Нагрузочная граница одновременных потоков проверяется в WP-11.
