ADR-049: Список CalculationSnapshot по точной ревизии и серверные размер/MIME отчёта
Статус: принято и реализовано
Дата: 2026-10-31

Контекст

Сравнение «прогноз против наблюдения» (WP-09) и ссылки на расчёты требовали вручную вводить
UUID CalculationSnapshot: контракт 1.11.0 не давал операции, перечисляющей снимки ревизии.
Карточка отчёта (ADR-045) показывала SHA-256, но не размер и тип файла, хотя PostgreSQL уже
хранит byte_size и media_type в export_artifacts. Клиент не должен выводить эти значения сам.

Решение

1. Canonical contract 1.12.0 аддитивно добавляет GET /v1/calculations (listCalculations,
   роль viewer) с обязательным query scenario_revision_id, cursor и limit 1..200 (50 по
   умолчанию) и схему CalculationSnapshotPage {items, next_cursor}. POST startCalculation на
   том же пути не меняется.
2. Сервер сначала авторизует ревизию тем же путём, что getCalculation: город, видимость
   сценария, ограниченные наборы данных, правила, ставки и модели ревизии. Недоступная или
   чужая ревизия даёт 403/404 и не раскрывает число снимков. Отзыв grant закрывает чтение.
3. Возвращаются только снимки с точно равным scenario_revision_id, без родительских/дочерних
   ревизий и без подстановки «последнего похожего» расчёта. Элемент совпадает с getCalculation,
   включая is_stale относительно текущей ревизии сценария; unknown/null не заменяются нулём.
4. Пагинация использует общий keyset по id: курсор связан с операцией, пользователем и
   фильтрами, поэтому чужой или изменённый курсор даёт 422 invalid_cursor. Снимки неизменяемы,
   поэтому страницы стабильны; новые снимки не дублируют уже выданные элементы.
5. ExportArtifact получает обязательные серверные byte_size (целое >= 1) и media_type
   (application/pdf или XLSX MIME) из реестра export_artifacts. Значения записываются один раз
   при атомарном сохранении файла и сверяются с файлом при скачивании (ADR-045). Старые поля и
   операции не меняются; миграция не нужна, потому что столбцы уже есть в 0028.

Последствия

- UI WP-09 выбирает снимок из списка ревизии вместо ручного ввода ID.
- Отчёт показывает размер и тип файла из ответа сервера, а не из скачанного blob.
- Python и TypeScript клиенты перегенерированы атомарно вместе с контрактом.
- Клиенты 1.11.0 продолжают работать: новые пути и поля только добавлены.
