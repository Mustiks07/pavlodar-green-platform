ADR-001 Модульный сервер и общие контракты
Статус: baseline спецификации 1.0.0, подлежит совместному review в WP-00.

Проблема: два агента должны создать один продукт с транзакциями, общими данными,
быстрым интерактивным UI и долгими пространственными/физическими расчётами.

Решение: FastAPI modular monolith для domain/API и отдельные Celery workers.
PostgreSQL/PostGIS - долговременная истина; Redis - очередь/кеш; outbox в БД.
Frontend React/MapLibre/Three, canonical OpenAPI и generated TypeScript client.
Сценарии/расчёты неизменяемы по версиям; UI не имеет второй финансовой модели.

Почему: сохраняются целостность и простая интеграция двух агентов; тяжёлые
вычисления масштабируются отдельно. Отказ worker не обязан останавливать карту.
Разделение на независимые микросервисы сейчас добавит контрактов и распределённых
транзакций без доказанного выигрыша. Переход возможен по измеренным ограничениям.

Следствия: единый migration owner; модульные интерфейсы; bounded jobs, idempotency,
transactional outbox; статические тайлы отдельно от изменяемой проектной БД.
Нет обязательной платной картографической подложки; стоимость инфраструктуры остаётся.

Проверка: WP-00 compatibility; WP-01 сохранение/auth; WP-11 crash/retry/load/restore.
Альтернатива Cesium для реальных 3D Tiles/photogrammetry рассматривается отдельно,
если организаторы предоставят такой набор. Она не внедряется только ради эффекта.
